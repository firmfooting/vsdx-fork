# Roadmap: vsdxkit modernisation

Distribution `vsdxkit` (import `vsdx`), fork of `dave-howard/vsdx`.
Base: upstream v0.6.1 plus the Visio-faithful feature set recorded in the git history.

## Released base

- [x] v0.6.3 tag and wheel built.
- [x] `pyproject.toml` packaging; package version single-sourced from
      `vsdx.__init__.__version__`.
- [x] Distribution renamed to `vsdxkit`; import namespace remains `vsdx`.
- [x] Python 3.10–3.14 support; Python 3.7–3.9 dropped.
- [x] `py.typed` included in the wheel.
- [x] `vsdxfile.py` split into inspectable units: master import in `masters.py`,
      Jinja rendering in `templating.py`, and package/XML persistence in
      `xmlio.py`.

## R1 — CI rebuild ✅

- [x] SHA-pinned GitHub Actions with top-level `permissions: {}` and
      per-job `contents: read`.
- [x] pytest matrix across Python 3.10–3.14 on Ubuntu and Windows.
- [x] ruff, pyrefly and distribution-build jobs.
- [x] generated wheel and sdist retained as CI artefacts.
- [x] Sphinx documentation built with warnings treated as errors.
- [x] dedicated zizmor workflow runs on every push to `main` and every pull
      request; actionlint and zizmor pass locally.
- [x] GitHub default branch, remote HEAD, CI triggers and documentation URLs
      renamed from `master` to `main`.

## R2 — ruff ratchet ✅

- [x] zero ruff findings; no `--exit-zero` escape hatch.
- [x] import ordering and formatting enforced in CI.
- [x] remaining `noqa: E402` sites document the package's deliberate circular
      import seam.

## R3 — strict typing ✅

- [x] pyrefly moved from `basic` to `strict`.
- [x] zero pyrefly diagnostics at warning severity across `vsdx/`, with no
      in-source type suppression comments.
- [x] public and internal contracts added across shapes, pages, geometry,
      connectors, containers, templating, media and package persistence.
- [x] shared `require_element`, `require_root` and `require_tree` helpers make
      missing required XML parts fail with a named error.
- [x] strict checking retained in CI.

## R4 — API and documentation

- [x] `save_vsdx()` with no filename writes through a same-directory temporary
      archive and atomically replaces the source; regression tests cover
      failure preservation, repeated saves, suffix-appending and named output.
- [x] shape deletion removes incident connectors and their `Connect` records.
- [x] README rewritten around the fork's actual installation and capabilities.
- [x] Sphinx guides added for shape creation, connectors, re-anchoring,
      swimlanes and Jinja templates.
- [x] stale class references, Python-version claims and upstream installation
      instructions removed from the docs.
- [ ] deprecate direct `Connect.create()` use in favour of
      `Page.connect_shapes()`.
- [ ] consolidate page removal behind one public operation with complete
      relationship and package-part cleanup.

## R5 — release engineering

- [x] changelog started from the fork's released base.
- [ ] publish `vsdxkit` to PyPI; until then installation is from GitHub.
- [ ] add a tag-triggered GitHub Release workflow for wheel and sdist assets.
- [ ] add the Microsoft Visio COM oracle as an explicit Windows release gate
      where a licensed runner is available.
- [ ] cut the next release after the strict/docs branch is merged and CI is
      green.

## R6 — next capability work

- [ ] create a complete blank Visio document without requiring a source file.
- [ ] broaden the bundled shape palette and document its visual contract.
- [ ] add more CFF orientations and layouts beyond the validated horizontal
      lane model.
- [ ] build higher-level layout primitives while keeping cell and relationship
      writes in their current single implementation paths.

## Non-goals

- Renaming the import namespace. Existing code continues to use `import vsdx`.
- Saving macro-enabled `.vsdm` files.
- Reimplementing Microsoft Visio's full layout engine.
- Folding the entire fork back upstream. Small universal fixes can continue as
  isolated upstream pull requests.
